# Release Doctrine Review

## Decision

Agent Churn Control v0.1.0 is approved as a narrow, local, skills-only duplicate-work control.

## Invariants

- Progress and churn remain separate facts.
- Complete first local actions may run without added planning ceremony.
- Equivalent accepted evidence should be reused.
- Changed work requires typed, prior-bound, single-use invalidation.
- Rate-limit state is advisory and never grants whole-task stop authority.
- Enforcement applies only to the named local action.
- Receipts remain content-free and retain external identifiers only as digests.
- Unknown usage and cost remain unknown without comparable authoritative evidence.

## Authority

The plugin may classify local actions, emit local receipts, validate packages, and report promotion readiness. It may not execute models, publish, install itself, change credentials, permissions, or scopes, spend, send external messages, or control the overall task.

## Public claims

Public copy may describe validated local behavior. It may not claim demand, conversion, retention, willingness to pay, guaranteed outcomes, causal model regressions, or OpenAI endorsement.

## Validation

The release requires versioned fixtures, unit tests, package integrity, public-tree safety checks, copy and asset review, PR-first GitHub flow, hosted CI, clean installation, and provider readback.

## Disposition

Pass for v0.1.0 when the candidate-bound release receipt and hosted promotion gates are complete.
